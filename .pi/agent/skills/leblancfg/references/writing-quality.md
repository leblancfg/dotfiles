# Writing Quality Checklist

Applied after cognitive voice emulation. These checks ensure the output reads as authentically human, not as AI-generated content wearing a persona mask.


## Humanization Checklist
* [ ] Use ASD-STE100 Simplified Technical English
* [ ] Optimize for clarity and unambiguity
* [ ] Prefer a lexical density somewhere under 50%
* [ ] Avoid jargon at all costs; that is, terms specific only to the codebase, problem, or
current agent session
* [ ] When writing docs, use Google developer docs style guidelines


## Quality Checklist

### Voice & Tone
- [ ] Active voice used throughout (passive only for deliberate emphasis)
- [ ] Contractions used where natural (not stiff formality unless the subject's profile calls for it)
- [ ] Hedging removed: "might," "perhaps," "it could be argued" replaced with direct statements
- [ ] Confident assertions: opinions stated as positions, not tentative suggestions

### Structure & Flow
- [ ] Lead with the point, don't build up to it
- [ ] One idea per paragraph
- [ ] Bold key terms on first use
- [ ] Heading hierarchy respected (no skipped levels)

### Formatting
- [ ] Be stingy with em-dashes. They are meant to be for asides, not connecting clauses.
- [ ] Bullet points for 3+ parallel items
- [ ] Use straight (not curly) quotes everywhere

### Clarity & Concision
- [ ] Every sentence earns its place — cut anything that doesn't add information or voice
- [ ] Jargon replaced with plain language (unless the audience expects technical terms)
- [ ] Pronouns have clear referents
- [ ] No throat-clearing openings ("It's interesting to note that...")

### Final Polish
- [ ] Read the opening sentence — does it hook or does it warm up?
- [ ] Read the closing — does it land or does it trail off?
- [ ] Count em dashes — more than 2 per 500 words? Replace some.
- [ ] Count "the" at paragraph starts — more than 2 in a row? Vary.
- [ ] Does this sound like a person wrote it, or like it was generated?
